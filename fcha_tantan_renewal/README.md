# 프차 탄탄 · 블루 리뉴얼

선택한 디자인: 2안 TT 로고·검색 패널 + 3안 브랜드 카드·메인 배너·하단 안내.
기존 Django 프로젝트를 유지한 전체 실행본입니다. 기존 자료와 DB는 함께 포함했습니다.

## Windows 실행

1. ZIP을 **새 폴더**에 압축 해제하세요. 작업 중인 폴더 위에 바로 덮어쓰지 마세요.
2. `start.bat`을 실행하세요. Python 3.10 이상이 필요하며 3.12/3.13을 권장합니다.
3. 최초 실행 시 가상환경과 의존성을 설치합니다. DB 변경이 필요할 때는 자동 백업 후 migration을 실행합니다.
4. 브라우저에서 http://127.0.0.1:8000/ 를 여세요.
5. 우측 햄버거 메뉴 → 회원가입으로 직접 계정을 만드세요. 미리 만든 관리자·회원 계정은 없습니다.

직접 실행하려면 프로젝트 폴더에서:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/prepare_db.py
.\.venv\Scripts\python.exe manage.py runserver
```

## 동작

- 브랜드 비교는 최대 2개. 예전 세션의 3개 선택은 첫 2개로 정리합니다.
- 비교 표 체크박스로 그래프 항목도 최대 2개 선택합니다. 데스크톱 오른쪽 그래프는 스크롤을 따라갑니다. 항목마다 단위·눈금을 독립 표시합니다. 모바일에서는 그래프를 표 위에 배치하고, 비교 표의 항목명과 브랜드명을 줄바꿈해 좁은 화면에서도 두 브랜드를 함께 표시합니다.
- 메인·검색·데이터 안내는 공개. 상세·지역 상세·비교·CSV·계산기·관심 브랜드는 로그인 필요. 상세 API도 차단하며 공개 목록 API는 요약만 제공합니다.
- 회원가입·로그인·POST 로그아웃을 구현했습니다. 비밀번호는 Django 해시로 저장하며 상세 링크 로그인 후 원래 페이지로 돌아옵니다.
- 관심 브랜드는 회원 계정별 DB 저장. 이전 비회원 세션의 관심 목록은 다른 회원에게 자동 이관하지 않습니다.
- 햄버거는 마우스오버/키보드 Enter/모바일 터치 지원. Escape·바깥 클릭으로 닫을 수 있습니다.
- 투자금 회수 계산기는 브랜드·연도별 매출/초기비용을 참고로 채우고 사용자 입력을 서버에서 검증합니다. 입력은 원래 브랜드 DB에 저장하지 않습니다.
- 모든 금액 입력은 **만원**, 비율 입력은 **%**입니다. 월 고정비는 월세+인건비+기타비용. 월 순이익=월매출−변동비−고정비. 회수개월은 초기투자금/양수인 월순이익을 올림합니다. 0 이하 이익에서는 회수 불가, 변동비율 100%에서는 월 BEP 산출 불가로 표시합니다.
- 기타 월 고정비와 변동비율은 선택 입력이며, 비워두면 0으로 계산합니다. 모든 숫자 입력은 정수이며 위·아래 버튼은 1씩 변경합니다. 결과 금액은 소수점 없이 반올림 표시하고 회수 개월은 반올림 전 순이익으로 계산합니다.
- 상단 GNB의 지원 정보를 회수 계산기로 교체했습니다. 로그인 시 상단에 닉네임과 ‘님’을 표시합니다.
- 같은 페이지의 필터·정렬·연도 변경과 비교/관심 담기·계산 시 스크롤 위치를 복원합니다. 지역 목록 펼침에 포인터를 표시하고, 체크박스 아이콘 중앙 정렬과 전반적인 글자 크기를 조정했습니다. 브랜드 카드 전체를 상세 링크로 연결하되 비교 담기와 관심 버튼은 각각 동작합니다.
- 비용은 직접 입력해야 합니다. 미입력 세금·이자·감가상각·점주 급여 등은 자동 추정하지 않습니다. 기타 고정비에 입력할 수 있습니다. 매출/비용이 일정하다는 가정의 단순 시뮬레이션입니다.

## 데이터 유지·평당 매출

- 기존 `brands_brand` 8행, `brands_annualstat` 16행, `brands_regionalstat` 272행의 값과 ID를 유지했습니다. 모든 원본 XLSX와 `brands/data/brands.json`도 바이트 단위로 보존했습니다.
- `backups/original_20261021.sqlite3`는 업로드한 ZIP의 원본 DB입니다. 실행용 `db.sqlite3`에는 신규 migration만 반영했습니다.
- 기존 모델/필드를 지우거나 이름을 바꾸지 않았습니다. 신규 테이블은 `brands_areasales`(확인된 평당 연매출), `accounts_savedbrand`(회원별 관심 브랜드)입니다. 사용자 입력 계산값은 저장하지 않습니다.
- `커피 자료.xlsx`에는 실제 커피 브랜드 5개의 평당 매출 상·하한이 있으나, 현재 DB는 별개의 가상 브랜드입니다. 통화 배율/연월 단위도 해당 표만으로 확정할 수 없어 가상 브랜드에 임의 연결하거나 평균값으로 합치지 않았습니다. 원시 범위 20개를 `data/area_sales_review.json`에 원본 셀 좌표와 함께 정리했습니다.
- 상세/비교 화면의 **공시 평당 매출**은 확인된 자료가 없으면 ‘미제공’입니다. **비용 기준 면적 환산 월매출**은 월매출/견적 면적(평)으로 계산한 별도의 참고값이며 실제 평균 점포 면적/공시 평당 평균과 다릅니다.
- 확정 자료 연결: `docs/area_sales_template.csv`에 브랜드 ID·연도·평당 평균 연매출(원/평·년)·출처를 입력 후 `python manage.py import_area_sales 파일.csv`를 실행합니다. 기존 브랜드·연도만 연결하며 오류 시 전체 취소됩니다. 가상 자료는 명시적으로 `--demo`를 붙여야 합니다. 단위 미확인 raw 범위를 이 CSV에 바로 복사하지 마세요.
- 기존 버전에서 가입한 회원·관심 브랜드 또는 실제 데이터를 추가한 최신 DB가 있다면, 이 ZIP의 DB로 덮어쓰지 마세요. 해당 DB를 백업한 뒤 새 코드에서 `scripts/prepare_db.py`로 migration만 적용하세요.

## 검증

`python manage.py test` — 기존 데이터 수집/페이지 테스트와 리뉴얼 테스트 총 20개.
`python manage.py check` — Django 설정 및 모델 점검.
`docs/RENEWAL_VERIFICATION.md` — 데이터 보존·화면 검증 기록.

## 배포 전 설정

현재는 로컬 개발 실행본입니다. 공개 서버에서는 `DJANGO_DEBUG=0`, 임의의 `DJANGO_SECRET_KEY`, 실제 도메인 ALLOWED_HOSTS, HTTPS/보안 쿠키 등을 서버 환경에 맞게 설정하세요. 복구용 원본 DB와 원본 데이터 파일을 공개 정적 폴더로 배포하지 마세요.
