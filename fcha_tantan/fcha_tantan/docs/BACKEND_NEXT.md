# 김민기의 백엔드 작업 순서

1. README의 Django 실행 명령으로 화면과 DB가 연결되는지 먼저 확인합니다.
2. 원본 API/CSV를 별도 raw 폴더에 보관하고 원자료의 기준연도·단위·지표 정의를 확인합니다.
3. Pandas로 브랜드 고유 식별자, 업종, 지역명을 정규화합니다. 브랜드 이름만으로 조인하지 않습니다.
4. 공시의 가맹점 평균 연매출은 원 단위로 환산합니다. 본사 매출은 가맹점 평균 매출로 사용하지 않습니다.
5. 실제 폐업 데이터가 없으면 closed를 빈칸으로 둡니다. 계약종료+계약해지를 폐업으로 대체하지 않습니다.
6. docs/sample_stats.csv와 같은 열로 CSV를 만들고 import_stats를 실행합니다.
7. 관리자에서 실제 브랜드의 사진·설명·비용을 입력합니다. 표본 수/자료 기준일 등 필드를 필요에 따라 추가합니다.
8. 전국 합계와 지역 합계, 같은 연도/가맹점만 비교하는지 확인합니다.
9. 수천 개 브랜드로 확장되면 Django API에서 검색·필터·정렬·페이지네이션을 처리하고 api.js를 연결합니다.
10. 실서비스 전 데이터 검수, 실제 폐업 정의, 계약/비용 범위, 로그인/권한, 운영 DB와 배포를 진행합니다.

지금은 별도 DRF/React 없이 Django JsonResponse와 일반 JavaScript로 연결했습니다.
프런트에서 fetch하는 곳은 dist/js/api.js 한 곳입니다.
Django로 실행하면 config.urls.frontend가 API 모드로 자동 전환합니다.
정적 서버로 API를 별도로 연결할 경우 dist/js/config.js의 mode/apiBase를 바꾸고 서버 측 CORS를 명시적으로 설정해야 합니다. 권장은 동일 출처 구성입니다.
